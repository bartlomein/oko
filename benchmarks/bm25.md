## Implementation choice

We evaluated the Rust [bm25 crate](https://docs.rs/bm25/latest/bm25/) and
[Tantivy](https://docs.rs/crate/tantivy/latest/source/ARCHITECTURE.md). Oko already
has cached, borrowed chunks and an identifier-aware tokenizer, so a small scorer
inside that cache avoids a new search-engine abstraction and dependency.

The scorer uses `k1=1.2`, `b=0.75` and positive IDF, following the documented
[Lucene defaults](https://lucene.apache.org/core/9_6_0/core/org/apache/lucene/search/similarities/BM25Similarity.html).
For each query term and field:

```
idf = ln(1 + (N - df + 0.5) / (df + 0.5))
score = idf * tf * (k1 + 1) / (tf + k1 * (1 - b + b * length / averageLength))
```

Oko combines independent fields as `contentScore + 0.3 * pathScore`. This is a
weighted sum, not BM25F or exact Lucene score parity. Each chunk is a document;
empty fields count in corpus averages and N. This is an explicit Oko choice.
Filtering to source files changes eligibility but retains full-corpus statistics.
Query terms are deduplicated and sorted before floating-point accumulation.
The existing tokenizer, Porter stemmer, chunk boundaries, deterministic ties,
request budget and Jev controller remain unchanged. Scores are not probabilities.

During validation, the TypeScript reference scorer was updated to the same
behavior for differential checks. That reference and its comparison tools have
since been removed; Rust tests now cover the implementation directly.

## Why it helped

The independent local candidate audit compared the old and new release libraries
without calling Jev. The expected implementation was present in the initial
shortlist and survived the request budget for 14/15 questions before BM25 and
15/15 afterward. The optional-values helper moved from outside the top30 to
position2. It was then returned first in all six live ordinary/deep trials.

Expected initial ranks changed as follows:

| Question | Before | BM25 |
|---|---:|---:|
| strava-token | 7 | 2 |
| project-save | 2 | 1 |
| racebox-import | 1 | 1 |
| update-check | 6 | 1 |
| gapless-eligibility | 5 | 1 |
| optional-values | outside top30 | 2 |
| road-slope | 1 | 1 |
| gpx-repair | 1 | 1 |
| export-size | 1 | 1 |
| disk-space | 5 | 1 |
| mach-speed | 6 | 2 |
| unicode-path | 1 | 2 |
| intel-mitigation | 5 | 1 |
| parser-dispatch | 1 | 1 |
| centisecond-time | 1 | 1 |

The remaining first-result miss in every mode/repeat is Mach speed: Jev puts
the speed-formatting caller first and the expected numerical helper second.
The fixed labels were not broadened after observing this result. Deep mode adds
latency without improving these aggregate scores; ordinary search remains the
default. Fresh held-out repositories/questions are needed for broader claims.
